## Plugin layout (Claude Code 2.1.332, docs read 2026-11-25)

Sources: code.claude.com/docs/en/plugins/manifest-reference, /docs/en/skills, /docs/en/plugins/create-marketplace.

- `.claude-plugin/plugin.json` at the plugin root; only `name` is required. Also: `version`, `description`, `author` (`name` required), `homepage`, `repository`, `license`, `keywords`, `skills`.
- Skills: the default scan is `skills/<name>/SKILL.md`. The `skills` key adds directories, each either a folder of skill folders or one folder holding `SKILL.md` directly. So `"skills": ["./skill"]` loads the existing `skill/` folder with no move, which keeps the ClawHub path unchanged.
- Script paths: in a skill body Claude Code substitutes `${CLAUDE_SKILL_DIR}` (the folder holding `SKILL.md`) and, in a plugin, `${CLAUDE_PLUGIN_ROOT}`. These are not set in the Bash tool's environment; they are substituted into the Markdown. `node ${CLAUDE_SKILL_DIR}/scripts/sxsw.ts` works both as a plain skill and inside the plugin.
- Per-user data: `${CLAUDE_PLUGIN_DATA}` (`~/.claude/plugins/data/<id>/`) survives plugin updates; `${CLAUDE_PLUGIN_ROOT}` changes on update and must not hold state. This is the natural `SXSW_DATA_DIR` default for refreshed data in step 5.
- Frontmatter: `metadata` is a free-form map Claude Code does not act on, so `metadata.clawdbot` can stay.
- Validation: `claude plugin validate <dir>` exists. A scratch plugin with `{"name":"sxsw","skills":["./skill"]}` and the current `SKILL.md` validated with 0 errors (warnings: no version, description, author), and listed the skill as `sxsw:sxsw-skill`.
- Local install: `claude --plugin-dir <checkout>` loads it for one session.
- A self-hosted marketplace would add `.claude-plugin/marketplace.json` with `name`, `owner` and a `plugins` array whose entry has `"source": "./"`; users register it with `claude plugin marketplace add` and install from it. Not added until the owner decides whether the plugin is offered publicly.
